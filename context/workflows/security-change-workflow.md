# Security Change Workflow

1. Identify the trust boundary, protected asset, and authorized change.
2. Load the exact security control plus application/domain rules.
3. Inspect current enforcement and alternate entrypoints.
4. Define allow/deny and failure cases, data handling, and compatibility.
5. Implement within scope; preserve evidence privately when sensitive.
6. Test direct API/alternate access, denial, expiry/revocation, and recovery as relevant.
7. Update affected context and record residual risks factually.

WF-SECURITY-001 MUST not convert documentation gaps into a claim of an exploitable vulnerability. WF-SECURITY-002 MUST not broaden authority to active scanning, credential changes, or external disclosure without scope.
