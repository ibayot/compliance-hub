# Release Workflow

1. Verify acceptance scope and completed evidence.
2. Read the application's release/version/changelog overlay.
3. Align version sources, artifacts, schema/configuration prerequisites, and rollback.
4. Author curated notes for each intended audience.
5. Verify data-managed note idempotence and audience filtering when applicable.
6. Prepare deploy/runbook instructions and required environment artifacts.
7. Execute publication/deployment only within granted authority.
8. Report the actual release state and remaining action.

WF-RELEASE-001 MUST not label a prepared artifact as deployed. WF-RELEASE-002 MUST keep internal technical maintenance out of user-visible changelog text.
