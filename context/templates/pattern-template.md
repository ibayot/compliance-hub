# General Pattern Template

## Metadata
ID: unique category/topic. Status: candidate/draft/baseline/active/deprecated.
Scope, triggers, owner, version applicability, last reviewed, dependencies, canonical implementation, and enforcement.

## Guidelines
State the preferred approach and when it applies.

## Why
Explain the failure or cost the pattern prevents.

## Structure
Provide a minimal implementation structure. Label pseudocode and unimplemented examples clearly.

## Implementation
Describe ownership, boundary/lifecycle, contracts, persistence/configuration, and failure handling. Use Store Implementation when this concerns actual client/application state.

## Rules
Use stable IDs and normative strength. One declaration per ID. Link related rules instead of duplicating their text.

## Variants and Exceptions
Describe legitimate alternatives, scope, and the exception process.

## Security and Accessibility
Add relevant controls and link their authoritative patterns; mark truly inapplicable concerns explicitly.

## Validation
List meaningful checks, actual enforcement, required evidence, and known gaps.

## Related Patterns
Use relative Markdown links to existing documents.
