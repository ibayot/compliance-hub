# Compliance Hub Workspace and Mobile

Use the shared [web UI and UX](../../design-system/page-patterns/web-ui-ux-pattern.md) and [mobile UI and UX](../../design-system/page-patterns/mobile-ui-ux-pattern.md) guides for task-level design and validation.

## Layouts and actions

Operations, Sectioned and Split Pane are presentation presets. Keep the capability-filtered sidebar groups, navigation spacing and type consistent between presets. The shell and breadcrumb surface follow the selected palette and light/dark mode. Use the same permitted actions, filters, data and deep links across presets. Use a side rail for compact filters or expandable Duties Map day details. Keep multi-field Report Builder parameters in the main content area, where they have room to wrap.

On phone widths, use the shared shell Back arrow for nested routes. A direct link falls back to an authorized parent. Page-owned Create/Add and Update controls may register a labelled plus or pencil shortcut with the shell. Show it only when the original is outside the usable viewport and keep its shadow local to the button. Include the fixed navigation, safe area and software keyboard when checking which controls are reachable. [Mobile navigation](../../../frontend/src/contexts/MobileNavigationContext.tsx) and [page action](../../../frontend/src/components/layout/MobilePageAction.tsx) are the shared owners. See DS-APPNAV-005/006 and DS-RESPACTIONS-006/007.

Use a compact mobile vertical rhythm across stacked cards and forms. Reduce section, card, and field gaps before shrinking text or controls; keep touch targets at least 44px high and let long values such as unit names wrap instead of clipping. Keep desktop spacing unchanged unless the task also targets desktop.

At phone widths, page frames, workspace regions, card surfaces, and form controls fill their available parent width with a small consistent safe-area-aware gutter. Remove nested container gutters that leave a second unused inset. Keep intentional desktop columns and compact inline actions; do not stretch badges or icon-only controls into full-width rows.

Anchor the mobile bottom navigation to the viewport with fixed positioning and safe-area padding; do not put it in document flow or rely on `position: sticky` for the app-wide navigation. Reserve bottom space in the main content for the bar, its safe-area inset, and any visible floating page action so the navigation does not cover the final control. Verify while scrolling a long page and while browser chrome expands or collapses; test the installed iOS viewport separately. Use [shared sticky tabs](../../../frontend/src/components/layout/StickyTabs.tsx) within the same scroll region as their panels. A tab in its own header band sticks with the band. Nested tabs clear the primary tab row, and an opaque surface keeps the scrolling content legible behind each header.

Keep Comments and Timeline in the same equal-height row where the Ticket Details width permits, and make escalation details conditional on an existing escalation. Ticket Details and Staff Directory share the profile-photo viewer. Verify the actual requester photo, the keyboard-accessible enlargement, portrait and landscape aspect ratios, and a usable fallback when no photo is available. Check ticket filters in focal-only and ticket-management accounts, including that Escalated To Me sits with the other filters. Scroll populated tables in each preset, then check a short result, an empty result and mobile Attendance's day view. See [canonical implementations](../../inventory/canonical-implementations.md) and DS-TABLE-006.

## Retest cases from owner feedback

Use these cases when related work is requested. They record places where a broad completion claim missed a visible requirement or interaction. Establish the current result by retesting the affected state.

| What was missed | Check before claiming it is done |
| --- | --- |
| A total revamp was reported while changes were concentrated on a few routes and some presets mainly differed by styling. | Inventory the requested page families, including tickets, duties, reports, documents, directory, settings and administration. Compare the same populated state across relevant presets. Report which families and presets were actually inspected. |
| Duties Map side details and the Ticket Details comment/timeline placement were missed. | Select an occupied day and expand an item in the side panel. Open a populated ticket wide enough for the requested row and inspect Comments and Timeline together. Check the escalation section with and without an escalation. |
| The requester avatar was shown as initials or could not open the full photo. | Open a ticket filed on another person's behalf, verify the displayed photo belongs to the actual requester, open and dismiss the enlarged photo, and check the missing-photo fallback. |
| Escalated To Me appeared in a separate oversized container for an escalation focal. | Render the same preset for focal-only and ticket-management accounts. Check the button placement and size with the filters actually available to each account. |
| The Sectioned ticket header showed overlapping rows while scrolling, and short lists left a large blank area. | Scroll a populated list in its actual container, then filter to one row and to zero. Observe header position, row overlap, scrolling and container height. |
| Floating mobile buttons duplicated visible page controls. | Scroll the original action into and out of view in both directions. Check the shortcut invokes the same action and does not obscure inputs, feedback or navigation. |
| Safari's address bar and the Home Screen viewport could leave the bottom navigation floating away from the visible edge. | On iPhone, scroll through the middle of a long page with Safari's toolbar expanding and collapsing. Repeat from a Home Screen launch and check that the navigation stays at the visible bottom, the Home indicator has space, and any floating shortcut stays above the navigation. |
| Back from a ticket returned to the filters but lost the place in the list. | Open a ticket from partway down a later results page. Check both the shell Back arrow and browser Back return to the saved filters, page and scroll position after results render. Check direct links separately. |
| Ticket settings, rotation and user management relied on desktop tables on phones. | Check Keyword Rules, Escalation Focals, Duties Rotation and all three User Management tabs with populated cards. Check the same permitted actions, search and pagination against desktop. Expand a long exception in Duties Map after confirming its summary truncates. |
| Ticket reporting showed the wrong SLA classification after correction. | Start from a ticket whose effective correction changes its outcome, save via the correction flow, reopen it and check the weekly breakdown, including the relevant pause calculation. |

## Install and preview

- The [web install configuration](../../../frontend/public/manifest.webmanifest), [Android launcher](../../../frontend/android-launcher/src/main/AndroidManifest.xml), and [Capacitor wrapper](../../../frontend/capacitor.config.ts) use the shared web UI. **Download App** beside Notifications offers browser installation, the profile on iOS, and the approved signed download first on Android when configured or served by the deployment. The [Web Clip handler](../../../backend/src/apps/ios-webclip-profile.ts) derives its destination from deployment configuration, with loopback allowed for local use. Verify the installed result on physical devices, including icon, window chrome, sign-in, navigation and notification entry.
- On iOS, use the public [Safari install page](../../../frontend/public/install-ios.html) when checking a fresh Home Screen install. It stays on a static page during installation and advertises the [touch icon](../../../frontend/public/icons/compliance-hub-ios.png) and root fallback, which match the embedded profile icon. Verify the icon in Safari's add preview and on the Home Screen.
- The downloadable iOS profile combines the full-screen Web Clip and the public internal root CA certificate. After a manual profile install, users must enable full trust for the root CA in iOS Certificate Trust Settings; never claim the profile silently trusts it. The profile and APK may contain only the public root certificate, never its private signing key or the server private key. The Web Clip launches the configured HTTPS host at the protected dashboard. Verify the icon, actual launch address, certificate trust step, notification prompt and closed-app delivery. Safari installation remains a separate path whose alert result cannot prove profile support.
- Hide the iOS configuration action from installed Home Screen sessions. The profile points to the deployment URL and ordinary web releases use that same profile. Distribute a replacement when profile data such as the URL, label or embedded icon changes.
- On Android, keep Chrome's install prompt and Home Screen instructions available. The signed Trusted Web Activity launcher uses the site's existing Web Push through browser notification delegation and embeds the public root CA only to export it for Android's user-approved Settings installation. Chrome owns TLS validation for the TWA; Capacitor Network Security Configuration cannot change Chrome's trust. The launcher must remain blocked from opening the site until the exact bundled CA is present in Android's trust store. Android 11+ requires manual installation through Settings; never imply that the APK silently installs a CA. The Capacitor WebView requires its own background push integration. Verify the APK delivery headers, matching signing certificate in Digital Asset Links, certificate setup flow, and installed notification behavior separately. Permission and subscription require an explicit user action. Missing manifest, install assets, APK, or association file must return 404 instead of the app shell.
- For local phone checks, use the [phone preview script](../../../frontend/scripts/preview-phone.mjs) on the developer-selected private network interface and keep the phone on a network or VPN that can reach it. Android emulator routing and cleartext are debug-only. Use the [launcher build script](../../../frontend/scripts/build-android-launcher.mjs) for the downloadable APK and its matching statement. Keep signing material outside the repository and independently verify the installed artifact before distribution.
- [Notification policy](notifications.md) owns the web push and badge contract. Verify foreground, background and closed-app delivery, permission denial, account switching, sound and badge behavior on each supported installed/browser surface. Browser viewport checks establish layout evidence. Installed distribution and physical-device delivery need separate checks. See PLAT-MOB-DIST-004 and the [web platform patterns](../../platforms/web/INDEX.md).
