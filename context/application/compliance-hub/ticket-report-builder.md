# Monthly Ticket Report Builder

Active implementation contract, approved for personal templates, monthly summaries, optional sections/list columns and browser Print / Export PDF.

## Guidelines and rules

- CH-REPORT-001 MUST use Asia/Manila month boundaries, inclusive start/exclusive next-month start. Clip current months to generation time and label Month to date; reject future months. Received totals use filing time; completed totals and SLA use approved effective completion (CH-TICKET-006/007), including earlier filings completed this month. Exclude cancelled, duplicate and requester-closed records under their existing operational-statistics policy.
- CH-REPORT-002 MUST always include received/completed totals, SLA Met/Missed/unavailable/compliance, and separate pause/freeze affected-ticket counts, occurrence counts, business minutes, average frequency and duration. Compliance = Met / (Met + Missed) * 100; no classified tickets means unavailable. Saved deadlines determine SLA, with the existing active-business-time/allowance fallback only when usable. Missing completion timestamps cannot be placed in a completed month. Generation must not repair or mutate tickets.
- CH-REPORT-003 MUST capture actual explicit pause/freeze transitions separately from capped SLA credits, on the same ticket persistence operation. Capture automatic resume, queue promotion out of an explicit Pause, and accepted-escalation transitions. Same-status extensions are one episode. Queue waiting and calendar suspension are not explicit interruption occurrences. Keep history across SLA origin resets. New tickets have complete history; never backfill invented intervals for existing tickets.
- CH-REPORT-004 MUST clip intervals to the month, generation cutoff and effective completion, using the shared business-time calculator to exclude lunch/outside-hours/non-office days and include applicable ticket-specific OT dates. Actual interruption duration is not capped by SLA-credit allowances. A spanning episode counts once in each overlapping monthly report; those counts are not additive as lifetime distinct occurrences. An overlapping episode can have zero business minutes.
- CH-REPORT-005 MUST distinguish unknown from zero. Monthly history is usable when complete from creation or capture began no later than the month start. With incomplete histories, label recorded counts/minutes as lower bounds, exclude incomplete tickets from averages and publish the eligible denominators. Average frequency = eligible occurrences / eligible affected tickets. Average duration = eligible business minutes / eligible occurrences. Undefined averages are unavailable. Preserve existing estimated active-time labels (CH-TICKET-009 / ADR-001); never infer exact typed intervals from old credits or asynchronous audits.
- CH-REPORT-006 MUST require report access and current-assignee scope for personal reports, and report-management authority for broader staff filters/breakdowns. Apply OT privacy before all aggregates/detail projections. Current assignment and calendar settings are not historical snapshots. Templates never grant access. Template owner comes only from authentication, with owner-scoped reads/writes, unique names per owner and stale-revision conflicts.
- CH-REPORT-007 MUST keep required metrics server-owned and unremovable. Optional lists select received/completed/recorded-interruption membership. Required columns are ticket number, monthly pause/freeze counts/business minutes, history quality and completed-month SLA. Unknown historical events may be absent from interrupted-only lists; explain this. Sort the whole list with an ID tie-break before UI pagination. Preview and print reuse one generated response; changed settings require regeneration. Print all rows, with text-safe rendering.

## Structure and store implementation

Presentation scope under CH-REPORT-006/007: one-person reports use the actual selected account name, including the current account for personal reporting. Omit the redundant staff comparison section and assignee list field in one-person configurations and responses; retain both for authorized all-staff reports. Shared preview/print metadata includes the generated response's support-type filter, explicitly labelling an unrestricted selection as All support types (DOMAIN-REPORT-001). Keep the timezone in calculation metadata but omit its label from displayed/exported headers. Short section titles and `SLA` use the period/basis description to explain membership. Existing saved configurations are scoped again when used.

Scoped readability variant: [ticket-list presentation](../../../frontend/src/components/ticket-reports/ReportTicketList.tsx) defaults to detail cards, with an optional scrollable table that gives columns usable widths, sticky colored headers and a highlighted ticket-number column. Print all selected details as field-labelled cards rather than squeezing every column into one page width. Keep the same generated data and mandatory interruption/SLA values in both layouts. `Not recorded` denotes unavailable exact interruption history, `Incomplete` denotes partial-period coverage, and neither means zero or changes SLA classification.

Report presentation variant: label the required section Monthly Summary. Render period/account/support/generation metadata bold and italic at the existing font size in preview and print. Issues includes its category and retains separate category/issue identities, even when labels repeat. Each listed ticket carries its server-projected support type independently of optional columns. Use shared blue Desktop, teal IT, purple Pantawid ICT and orange Specialized outlines, with a text legend and a support-type label on each card; unknown types have a neutral labelled fallback. Reuse the same mapping for printed cards and the table's row-identity accent (FND-A11Y-004). These report-outline colors are a scoped variant, not a replacement for status, priority or SLA colors elsewhere.

The [controller](../../../backend/src/modules/tickets/controllers/ticket-report-builder.controller.ts) authenticates and validates; the [builder service](../../../backend/src/modules/tickets/services/ticket-report-builder.service.ts) owns template persistence and projection; the [ticket service](../../../backend/src/modules/tickets/services/ticket.service.ts) owns scoped source queries and existing SLA/calendar calculations. [Configuration](../../../backend/src/modules/tickets/services/ticket-report-builder.contract.ts) defines exact input allowlists. [Interruption capture](../../../backend/src/modules/tickets/services/ticket-interruptions.ts) is independent of the SLA-credit ledger.

The [builder UI](../../../frontend/src/components/ticket-reports/TicketReportBuilder.tsx) owns unsaved controls and transient preview. Identity/report-management changes invalidate pending preview responses and clear their generation state so another authorized preview can run. [Shared presentation](../../../frontend/src/lib/utils/ticket-report-presentation.ts) supplies identical preview/print sections and warnings. Saving a template stores configuration, not report data. No new library, process or worker; shared templates, archived snapshots and spreadsheet exports are outside this version.

## API contract

Authenticated shared transport: `/api/tickets/report-builder` (gateway also supports `/api/v1`). Every operation requires `isTicketReportsAccess`.

| Method and suffix | Contract |
| --- | --- |
| GET `templates` | Up to 100 personal templates, stable name/ID order |
| POST `templates` | `{ name, configuration }`, 201 |
| PATCH `templates/:uuid` | `{ name, configuration, revision }`, owner/revision checked |
| DELETE `templates/:uuid?revision=N` | Owner/revision checked, 204 |
| GET `staff-options` | Authorized assigned staff IDs/names; additionally requires `isTicketReportsManage` |
| POST `preview` | `{ year, month, configuration }`, 200; no ticket mutations |

Configuration: title (trimmed 1–120 characters); sections (`categories`, `issues`, `staff`, `ratings`); includeTicketList (boolean); listBasis (`completed`, `received`, `interrupted`); columns (`subject`, `description`, `requester`, `assignee`, `category`, `issue`, `status`, `priority`, `createdAt`, `completedAt`); sortBy (`ticketNumber`, `createdAt`, `completedAt`); sortOrder (`asc`, `desc`); ticketType (approved support type or null); technicianId (positive integer or null). Reject unexpected keys, unknown/duplicate array values and invalid ranges. Template names are trimmed 1–80 characters. Save as new requires a distinct name.

Response: configuration, month/cutoff/generation metadata, scope label, mandatory summary, requested completed-month breakdowns/ratings and selected rows. Source limit 10,000 tickets; exceeding it explicitly asks for narrower staff/support filters, without partial results. Staff suggestions are bounded to 2,000 assigned IDs. Description is optional and retrieved/exported only for an explicitly enabled list with that column selected, under the same authorized ticket scope. Before fetching descriptions, bound their aggregate source text to 5 MiB; reject oversized reports instead of silently truncating. Preserve description text/newlines, encode it safely and render it at full card width in preview/print. Comments, attachments and employee IDs remain excluded. Errors: 400 invalid/range/size; 401 unauthenticated; 403 scope; 404 missing/foreign template; 409 stale/name conflict; 503 calendar/directory outage.

## Data, release and validation

Ticketing owns nullable `tickets.interruption_history` and `ticket_report_templates`. Verify the target in environment-managed `db-init/20261027-add-ticket-report-builder-ticketing.sql` and apply after base/prior upgrades, before updated ticketing starts, for fresh and existing installs. Repeat application preserves rows/legacy credits, with no interval backfill. Retain additive storage on rollback. Older writers do not capture transitions; affected periods must be treated as incomplete before exact reporting resumes. Browser system Print / Save as PDF follows the current application workflow; native-device print availability requires separate validation.

Validate formula examples, corrected completion/month boundaries, deadline equality, lunch/weekends/OT, active/cross-month/zero-business-time intervals, automatic resumes/escalations, queue-resume interval closure and stale-history conflicts, incomplete history, foreign/stale templates, denied direct APIs, stable ordering, filtered preview/print metadata reconciliation, permission refresh during generation, and keyboard/narrow layouts. Validation artifacts stay ignored by Git. Related: DOMAIN-REPORT-001/002/003/004, SEC-SCOPE-001/002, DATA-QUERY-001/002/003/004, FND-UI-001.
