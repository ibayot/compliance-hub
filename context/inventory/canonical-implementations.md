## Updating the map
Local lessons mapped to reusable owners: APP-CH-007 uses [schema/runtime readiness](../data/schema-bootstrap-pattern.md); the [report contract](../application/compliance-hub/ticket-report-builder.md) specializes [report-builder guidance](../domain/report-builder-pattern.md); CH-ADMIN-009 specializes [established-identity validation](../security/identity/authentication-pattern.md); CH-ADMIN-008 specializes [client updates](../api-and-integrations/client-update-pattern.md) and [session lifecycle](../security/identity/session-pattern.md). Existing code evidence remains scoped to the linked implementations, not a whole-application compliance claim.

Staff ID verification during profile completion: `validateStaffId` in [Users service](../../backend/src/modules/users/users.service.ts) binds the unchanged-ID allowance to the authenticated current account; changed IDs retain list/duplicate checks (CH-ADMIN-009). Report detail-card/table rendering lives in [ReportTicketList](../../frontend/src/components/ticket-reports/ReportTicketList.tsx), sharing the preview/print field projection under CH-REPORT-007.

Monthly report configuration and actual interruption analytics: [backend builder](../../backend/src/modules/tickets/services/ticket-report-builder.service.ts), [capture](../../backend/src/modules/tickets/services/ticket-interruptions.ts), [UI](../../frontend/src/components/ticket-reports/TicketReportBuilder.tsx), [preview/print projection](../../frontend/src/lib/utils/ticket-report-presentation.ts). CH-REPORT-001 through CH-REPORT-007 govern personal templates, scoped metrics, required SLA fields and history-quality disclosure.
