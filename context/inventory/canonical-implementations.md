## Updating the map

Account recovery follows CH-ADMIN-010/011: [MFA recovery policy](../../backend/src/modules/users/mfa-recovery-policy.ts), [validated unlock input](../../backend/src/modules/users/dto/unlock-mfa.dto.ts), transaction-owned OTP issuance/consumption/unlock in [Users service](../../backend/src/modules/users/users.service.ts), protected [Users controller](../../backend/src/modules/users/users.controller.ts), and User Management in [Settings](../../frontend/src/app/%28app%29/admin/settings/page.tsx). The explicit `MFA_UNLOCK` audit is mandatory in the same transaction; no new capability column or schema is required.

Bounded read transport is [boundedGet](../../frontend/src/lib/api/bounded-read.ts), used by ticket reads and session/live-event setup. [AuthContext](../../frontend/src/contexts/AuthContext.tsx) owns cancellable current-attempt recovery; [shared client](../../frontend/src/lib/api/client.ts) owns the bounded cross-tab renewal lock; [useSse](../../frontend/src/lib/utils/useSse.ts) owns heartbeat monitoring and fresh-ticket reconnects. API-CLIENT-006 / API-SSE-006 specialize CH-ADMIN-008 without creating another token store or replaying mutations.

Ticket-list loading and recovery: `fetchTickets` in [Tickets page](../../frontend/src/app/%28app%29/operations/tickets/page.tsx) owns all three list scopes; live events queue one reconciliation during an active read. `readTicketData` in [ticket API](../../frontend/src/app/api/references.ts) bounds the full read (including authentication-interceptor waits) and propagates cancellation. Dashboard counts and on-demand escalation history have separate request identities and error states. CH-TICKET-017 / DS-SEARCHFILTER-003/006 govern query freshness, loading ownership and safe retry; no mutation is automatically replayed by the list loader.

Local lessons mapped to reusable owners: APP-CH-007 uses [schema/runtime readiness](../data/schema-bootstrap-pattern.md); the [report contract](../application/compliance-hub/ticket-report-builder.md) specializes [report-builder guidance](../domain/report-builder-pattern.md); CH-ADMIN-009 specializes [established-identity validation](../security/identity/authentication-pattern.md); CH-ADMIN-008 specializes [client updates](../api-and-integrations/client-update-pattern.md) and [session lifecycle](../security/identity/session-pattern.md). Existing code evidence remains scoped to the linked implementations, not a whole-application compliance claim.

Staff ID verification during profile completion: `validateStaffId` in [Users service](../../backend/src/modules/users/users.service.ts) binds the unchanged-ID allowance to the authenticated current account; changed IDs retain list/duplicate checks (CH-ADMIN-009). Report detail-card/table rendering lives in [ReportTicketList](../../frontend/src/components/ticket-reports/ReportTicketList.tsx), sharing the preview/print field projection under CH-REPORT-007.

Monthly report configuration and actual interruption analytics: [backend builder](../../backend/src/modules/tickets/services/ticket-report-builder.service.ts), [capture](../../backend/src/modules/tickets/services/ticket-interruptions.ts), [UI](../../frontend/src/components/ticket-reports/TicketReportBuilder.tsx), [preview/print projection](../../frontend/src/lib/utils/ticket-report-presentation.ts). CH-REPORT-001 through CH-REPORT-007 govern personal templates, scoped metrics, required SLA fields and history-quality disclosure.

Older operational report history follows [ADR-002](../decisions/ADR-002-historical-interruption-reconstruction.md): [reconstruction](../../backend/src/modules/tickets/services/ticket-interruption-reconstruction.ts) consumes status-only evidence loaded for the already-authorized report source. Estimates remain transient, with direct history taking precedence and partial/estimated values distinguished in preview/print. It does not replace the SLA-credit ledger or change saved deadlines.

Manual operational-unit synchronization follows CH-ADMIN-012: [UnitSyncService](../../backend/src/modules/users/unit-sync.service.ts) reads active work history, preserves manual overrides and audits per-account changes; the protected POST in [Users controller](../../backend/src/modules/users/users.controller.ts), typed [Users API](../../frontend/src/lib/api/users.ts), and [Settings](../../frontend/src/app/%28app%29/admin/settings/page.tsx) own confirmation, results and list refresh. This is separate from [staff-directory import](../../backend/src/modules/users/staff-directory-sync.service.ts).

Historical requester units follow CH-TICKET-018: [snapshot capture](../../backend/src/modules/tickets/services/ticket-unit-snapshot.ts) and [Ticket entity](../../backend/src/modules/tickets/entities/ticket.entity.ts) separate stored ticket history from the live account profile. Filing and requester correction in the Ticket service capture the value; Ticket Details renders it. The environment-managed migration and operator order are described in [database guidance](../../db-init/README.md).

Outbound recipient-unit controls follow CH-ADMIN-013: [validated settings](../../backend/src/modules/users/dto/update-security-config.dto.ts), [policy](../../backend/src/modules/users/outbound-email-policy.service.ts), [protected settings](../../backend/src/modules/users/security-config.controller.ts), [private decision endpoint](../../backend/src/modules/internal/internal.controller.ts), [service client](../../backend/src/common/http-clients/users.http-client.ts), [central email dispatch](../../backend/src/modules/tickets/services/email.service.ts), and [invitation outcomes](../../backend/src/modules/tickets/services/rating-invitation.service.ts). Trusted [authentication producers](../../backend/src/modules/auth/auth.service.ts) label security mail explicitly. Settings owns the selector; the Users service owns current unit eligibility; ticket snapshots and in-app feedback remain separate.
